# HiAdv 2 · Fase 0 (base) · Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** um HiAdv 2 que abre, faz login, mostra só as áreas do escritório, busca e mostra o "Seu dia", com design system próprio, instalável no celular e publicado em hiadv.com.br.

**Architecture:** aplicativo estático React + TypeScript (Vite) que fala direto com o Supabase atual (auth por e-mail e senha, RLS por escritório, RPCs existentes). As áreas passam a ser por escritório (tabela nova `escritorio_areas`). O design system é um conjunto de tokens em CSS mais componentes próprios sobre o Radix (só comportamento).

**Tech Stack:** Vite 6, React 19, TypeScript 5 (strict), TanStack Router e Query, @supabase/supabase-js 2, Radix UI primitives, vite-plugin-pwa, Vitest + Testing Library, Playwright + @axe-core/playwright.

**Spec:** `docs/superpowers/specs/2026-11-20-hiadv-v2-design.md`

## Global Constraints

- **Interface e textos:**
  - Interface em pt-BR; código e nomes técnicos em inglês.
  - Textos das telas em português simples, com verbos de ação ("Salvar", "Entrar"), sem "clique aqui".
- **Segredos e dados:**
  - Só a URL e a chave **publicável** do Supabase vão no front, via `VITE_SUPABASE_URL` e `VITE_SUPABASE_PUBLISHABLE_KEY`. Nunca a service_role.
  - Desenvolvimento e testes usam o projeto de teste `vzjjzgbwaswpgrojqkhv` com dados fictícios (escritório demo `00000000-0000-4000-8000-0000000000d1`). O projeto oficial `ntcowwgnazronmfrylcm` só recebe a migração depois de passar no teste.
  - Nenhum dado real em código, teste, seed ou captura de tela.
- **Acessibilidade:** contraste AA; foco visível; alvo de toque ≥ 44 px; `prefers-reduced-motion` respeitado.
- **Publicação:**
  - Hospedagem no GitHub Pages do repositório novo, domínio `hiadv.com.br`.
  - O arquivo `public/CNAME` contém exatamente `hiadv.com.br` e nunca é apagado.
- **Ética e IA:** a IA não gera código executável; ações externas ou irreversíveis pedem confirmação e ficam no log.
- **Sistema atual:** continua no ar (lanhiadvogados.com.br/hiadv/ e /equipe/). Esta fase não altera os arquivos dele.

## Review Focus

1. **Usuário sem escritório ou sem área ativa.** Deve ver uma mensagem clara ("Seu escritório ainda não tem áreas ativas. Peça ao Gestor Master para ativar.") e não uma tela em branco. Teste na Task 5.
2. **Papel `code` com dois escritórios.** O seletor troca o escritório, e a barra lateral e o "Seu dia" recarregam com os dados do novo escritório, sem sobrar nada do anterior em cache. Teste na Task 5.
3. **Sessão expirada no meio do uso.** Volta para o login com "Sua sessão terminou. Entre de novo." e, depois de entrar, retorna à tela em que estava. Teste na Task 3.
4. **Celular estreito (360 px) e teclado aberto.** A barra inferior não cobre campos nem a busca. Teste Playwright em 360×640 na Task 6.
5. **Supabase fora do ar ou sem rede.** As telas mostram "Não foi possível carregar. Tentar de novo" com botão, e nunca ficam girando para sempre. Teste na Task 7.
